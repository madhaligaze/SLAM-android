# SLAM — Android-приложение

Заполняет и отправляет форму SLAM (Microsoft Forms) за всю бригаду прямо с телефона.
Сервер для этого **не нужен**: движок заполнения работает на самом телефоне.

## Как устроено

| Часть | Где | Что делает |
|---|---|---|
| Движок | `app/src/main/java/kz/slam/app/engine/` + `assets/slam_engine.js` | Открывает форму в невидимом браузере телефона (WebView — встроенный в Android Chromium) и заполняет её. Перенос `SLAM-backend/engine/slam_filler.py` с теми же проверками: каждое значение перечитывается, «Далее» засчитывается только при смене страницы, «отправлено» — только при странице подтверждения |
| Тексты ответов | `engine/Answers.kt` | **Генерируются** из `SLAM-backend/engine/answers.py`: `python tools/gen_answers.py`. Руками не править |
| Отправка в фоне | `jobs/SubmitService.kt` | Служба с уведомлением: можно свернуть приложение и убрать телефон. Очередь бригад хранится в базе |
| Данные | `data/` | База на телефоне — источник правды для экрана. Пока доступен сервер, бригады синхронизируются (общие для всех бригадиров), а отправки отмечаются на нём: другие видят «Отправляется / Отправлено», и одну бригаду нельзя отправить дважды одновременно |
| Экраны | `ui/` | Список бригад и экран бригады (Jetpack Compose) |

Без сервера приложение работает полностью, но бригады видны только на этом телефоне;
накопленные правки и отметки досылаются, когда связь с сервером появится.
Адрес сервера — в «Меню → Настройки» (по умолчанию `https://slam-backend-production.up.railway.app`).

## Сборка

Нужны JDK 17 и Android SDK (путь — в `local.properties`: `sdk.dir=C:/Users/.../Android/Sdk`).

```
gradlew assembleDebug      # отладочная: app/build/outputs/apk/debug/app-debug.apk
gradlew assembleRelease    # для телефонов:  app/build/outputs/apk/release/app-release.apk
```

### Ключ подписи — не потерять

Боевая сборка подписывается ключом `keystore/slam-release.jks`, пароли — в `keystore.properties`.
Оба файла **не хранятся в git**. Сохраните их копию в надёжном месте: обновление,
подписанное другим ключом, телефон не установит поверх — придётся удалять приложение
вместе с его данными.

## Установка на телефон

1. Передать `app-release.apk` на телефон (мессенджер, кабель, диск).
2. Открыть файл, разрешить «установку из этого источника».
3. При первом запуске разрешить уведомления — по ним видно ход и итог отправки.

Обновление — так же: новый APK ставится поверх, данные сохраняются.

## Тесты

- `tools/engine_test.sh [--submit] [--bg] "ТЕСТ Имя 1|ТЕСТ Имя 2"` — прогон движка на эмуляторе/телефоне через adb
  (`--bg` — сразу свернуть приложение и погасить экран; `--submit` — **реальная** отправка).
- `tools/e2e_android.py` — сквозной тест интерфейса против локального сервера (нажимает на экран как
  пользователь, делает **реальные** отправки с ФИО «ТЕСТ…»).

Тестовые отправки помечайте: ФИО и рабочее место начинаются с «ТЕСТ».
